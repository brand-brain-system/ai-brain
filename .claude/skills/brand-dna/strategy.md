# Strategy: which process to run

Read the brain's `sub-context-docs/brand-profile-narrative.md`, `brand-lens.md` and `sub-context-docs/visual-vocabulary.md` first. Then:

| Situation | Process | Signals |
|---|---|---|
| No DNA yet: `sub-context-docs/visual-vocabulary.md` has no prompt modifier, or `brand-lens.md` has no proof inventory | `research.md`, then `write-up.md` | New brain; the first static ads, prompt pack or landing page are next; "brand DNA for X" |
| DNA exists | `refresh.md` | A date in `brand-context/brand-one-pager.md`; "update the brand DNA", "they relaunched", a new product, a new offer, or the export is older than three months |
| Only the export is wanted | `write-up.md`, step 3 only | "Give me the Brand DNA doc", "paste-ready version"; all fields already filled |

**Not this skill:**
- Personas and customer language: `persona-gap` mode A. This skill notes objections only where real customer words already exist
- Auditing the brand's ads by persona and awareness: `persona-gap` mode B
- Making ads or pages: `static-ads`, `offer-ads`, `new-landing-page` (they read what this skill writes)

**The brand gave us files** (guidelines PDF, press kit, logo pack, product photos): read every one before researching. They set the fields they cover; research fills the rest. Product photos and logos go in `assets/`.

**Stop and ask** only once, at the start, and only for what no public source can give: the brand's own files if we're working with them, and which product the DNA should lead with if the brand sells several. A brand that isn't a client gets no questions about its own files: research only.

**What comes next.** A static batch, prompt pack or landing page usually follows. Say which one the DNA now supports, and which it doesn't yet (e.g. "review templates need a verified rating first").
