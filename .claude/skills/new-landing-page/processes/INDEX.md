# Processes: new-landing-page

Run `apply-feedback.md` first on every run, then in this order. `strategy.md` decides whether the run stops after the approved copy (copy only) or continues to the page (full run).

**A. Plan the page**
- `pick-template.md` (step 1): the reviewer picks the template from the swipe file; open the run.
- `intake-brief.md` (step 2): fill `brief.md` and `brief.json` from the brain, settle the angle, pull the buyer's words (and the ad, only if one is named), check the brand can fill the template, ask once for the gaps.
- `write-page-copy.md` (step 3): fill `page.json` section by section, then the check and the two gates.
- `approve-copy.md` (step 4): the human gate: a one-row-per-section table in chat; the reviewer approves, edits or cuts in their reply. Nothing is built before this.

**B. Make the page**
- `build-draft.md` (steps 5 and 6): tokens, photos, the build, desktop and phone screenshots, visual comparison and functional browser QA.
- `review-and-revise.md` (steps 7 and 8): send the page itself, read the notes, the revision loop (the draft board only on request).

**C. Finish**
- `finalize.md` (step 9): the clean page, final browser-QA report, the README with receipts and the handoff list.

**Any time**
- `apply-feedback.md`: the learning loop. First step of every run, before the build, before every revision, and on "apply feedback".
- `build-template-cards.md`: build-time only: turn new swipe pages into templates.
