# Process — Learn From Edited Scripts

Experimental, not yet run. When the strategist hands back scripts they edited, cut or kept, turn the
difference into lessons so the next batch doesn't repeat the same mistakes.

## Required inputs

- The scripts as shipped (after both gates), from `sprints/<sprint>/ads/`.
- The strategist's versions: edited, deleted or kept as is.

## Execution

### Step 1 — Diff each script
Set the shipped draft beside the strategist's version, line by line. Sort every change into one of:
cut whole script, cut line, rewritten line, reordered beats, kept untouched.

### Step 2 — Get the why
For each change without a stated reason, ask once, in a short list. Don't guess a reason and store it
as fact; an inferred reason is labelled inferred.

### Step 3 — Capture
Each change with its reason becomes one trace through `self-improvement-intake`, with the shipped line
and the edited line verbatim. Whole-script cuts also record which process and reference produced them.

### Step 4 — Propose, don't apply
Group the traces. A pattern seen in two or more scripts is proposed as a change to the brand's
script-voice profile (banned-by-absence list, CTA shape, pacing). Nothing in the profile changes
until the strategist approves.

## Guardrails

- Never treat "kept untouched" as approval of every line; it is weak signal.
- One edit is a trace, not a rule.
