# Plan the iteration

Write two short files before editing.

## `iteration-brief.md`

- Baseline page and brand
- User's direction, quoted exactly
- Intended audience, angle, offer, or hypothesis when the direction names one
- Success check: what must be visibly or functionally true in the new version
- Constraints: claims, proof, assets, CTA destination, deadline, and anything out of scope
- Evidence required for materially new copy or claims

## `change-plan.md`

Use one row per section or shared system:

| Area | Baseline | Action | New direction | Preserve | Reason |
|---|---|---|---|---|---|

`Action` is `change`, `preserve`, or `remove`. Include shared systems such as navigation, CTA treatment, fonts, spacing, forms, analytics hooks, accessibility, and responsive behavior.

The plan should make the user's direction testable without inventing extra ambition. If their direction changes one angle, do not also reskin the page. If it asks for a visual reskin, do not rewrite the offer. Supporting changes are allowed only when the requested change would otherwise be incoherent; name them in the plan.
